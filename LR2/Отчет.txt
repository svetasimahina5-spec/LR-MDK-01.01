1. Постановка задачи
Требуется разработать консольное приложение на языке C#, которое позволяет планировать расходы по заранее заданным категориям бюджета. Каждая категория характеризуется названием, лимитом (в рублях) и уже потраченной суммой.

Логика работы программы:

Программа выводит список категорий с остатками лимита (лимит минус потрачено).

В цикле запрашивает номер категории и сумму планируемого расхода.

Ввод завершается, когда пользователь вводит 0 вместо номера категории.

План принимается только в том случае, если по каждой категории суммарная запланированная сумма (с учетом всех вводов по одной и той же категории) не превышает остатка лимита.

Если план корректен — остатки лимита уменьшаются, выводится общая сумма.

Если план некорректен — остатки не меняются, выводится сообщение о категории, по которой не хватило лимита.

В конце работы выводятся итоговые остатки лимитов по всем категориям.

2. Проектирование архитектуры
Программа разбивается на несколько классов, каждый из которых оформлен в виде отдельной статической функции. Класс Program (содержащий метод Main) выполняет только роль организатора: вызывает остальные функции и связывает их работу.

2.1. Модули (классы)
Класс	Назначение
BudgetCategory	Модель данных одной категории бюджета (название, лимит, потрачено, текущий остаток).
BudgetManager	Бизнес-логика: создание списка категорий, вывод списка, обработка плана, применение плана, вывод итогов.
InputHelper	Утилиты для безопасного ввода (число, номер категории, сумма).
Program	Точка входа, организация вызовов.
2.2. Декомпозиция по функциям
Класс BudgetCategory:

Хранит данные об одной категории и умеет считать остаток (GetRemaining()).

Класс BudgetManager:

CreateDefaultCategories() — формирует исходный список категорий.

PrintCategories(List<BudgetCategory>) — выводит категории с номерами и остатками.

ReadPlan(List<BudgetCategory>) — цикл ввода номера категории и суммы, накопление плана в словаре (Dictionary<int, decimal>).

TryApplyPlan(List<BudgetCategory>, Dictionary<int, decimal>) — проверяет, не превышает ли план остатки. Если всё хорошо — списывает средства и возвращает true, иначе выводит сообщение о проблемной категории и возвращает false.

PrintTotalExpenses(Dictionary<int, decimal>) — выводит общую сумму расходов.

PrintRemaining(List<BudgetCategory>) — выводит итоговые остатки по всем категориям.

Класс InputHelper:

ReadInt(string prompt) — запрашивает целое число с повторным вводом при ошибке.

ReadNonNegativeDecimal(string prompt) — запрашивает неотрицательную сумму с защитой от некорректного ввода.

(Примечание: ввиду использования строгого ООП подхода и словарей, методы ReadCategoryNumber и ReadPlan объединены в BudgetManager.ReadPlan, так как им нужен доступ к списку категорий).

2.3. Алгоритм работы Main
Создать список категорий.

Вывести заголовок и список категорий.

Считать план (словарь: номер категории → суммарная сумма).

Попытаться применить план:

если успешно — вывести общую сумму расходов;

если неуспешно — сообщение уже выведено внутри TryApplyPlan.

Вывести итоговые остатки.

2.4. Особенности реализации
Для накопления плана используется Dictionary<int, decimal>, где ключ — индекс категории (0-based), значение — сумма всех вводов по этой категории.

Суммы хранятся в decimal — это исключает ошибки округления, характерные для double.

Проверка плана выполняется без изменения исходных данных: сначала проверяются все категории, и только при полном успехе производится списание. Это исключает частичное списание (как и требовалось).

Ввод защищен методами InputHelper, которые используют int.TryParse и decimal.TryParse с повторным приглашением.

3. Ожидаемый результат
При корректном плане программа выводит общую сумму расходов и обновленные остатки. При превышении лимита — сообщение вида:

Недостаточно лимита по категории «продукты»: остаток 13500 руб., запланировано 14000 руб.
и остатки не изменяются.
